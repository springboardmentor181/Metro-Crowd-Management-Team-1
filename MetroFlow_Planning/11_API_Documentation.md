# MetroFlow — API Documentation

**Document 11** · Phase 1 Architecture · **CANONICAL API CONTRACT**
**Status:** Design artifact — not implemented. Endpoint/event names here are authoritative for the Backend (09), Postman collection, and Sequence diagrams (14).

- **Base URL:** `/api/v1`
- **Auth:** Supabase-issued **JWT** in `Authorization: Bearer <token>`. FastAPI verifies signature (Supabase JWKS/secret) and loads `profiles.role`.
- **Content:** `application/json`. Timestamps ISO-8601 UTC. Pagination: `?page=&page_size=` (default 25, max 200) → envelope with `meta`.
- **OpenAPI:** auto-generated by FastAPI at `/api/v1/openapi.json`, Swagger UI at `/api/v1/docs`, ReDoc at `/api/v1/redoc`.

---

## 1. Conventions

**Success envelope (lists):**
```json
{ "data": [ ... ], "meta": { "page": 1, "page_size": 25, "total": 725 } }
```
**Error envelope (RFC-7807-ish):**
```json
{ "error": { "code": "FORBIDDEN", "message": "Operator cannot apply recommendations", "details": {} } }
```

**Common query params:** `network`, `line`, `station_id`, `from`, `to`, `granularity` (`hour|day`), `page`, `page_size`.

**Roles per endpoint:** 🟢 any authenticated · 🔵 operator+ · 🔴 admin only.

## 3. Representative Request/Response Schemas

**POST `/api/v1/ai/predict/crowd`**
```json
// request
{ "station_id": "DEL001", "target_hour": "2024-12-29T18:00:00Z",
  "context": { "weather": "Clear", "holiday": false, "event": "None" } }
// response
{ "data": {
    "station_id": "DEL001", "target_hour": "2024-12-29T18:00:00Z",
    "crowd_level": "High", "passenger_count": 18240,
    "congestion_probability": 0.72, "confidence": 0.88,
    "model": { "name": "crowd_classifier", "version": "v1.0.0", "algorithm": "xgboost" },
    "estimated": true } }
```

**GET `/api/v1/congestion/heatmap?line=Blue%20Line&from=2024-12-01&to=2024-12-07`**
```json
{ "data": { "rows": ["DEL001","DEL002"], "cols": [0,1,2,"...",23],
            "values": [[0.1,0.2,"..."],[0.3,0.4,"..."]], "scale": "congestion_probability" },
  "meta": { "unit": "0-1", "cells": 48 } }
```

**GET `/api/v1/alerts?status=open&severity=critical`**
```json
{ "data": [ { "id":"...","type":"overcrowding","severity":"critical",
  "station_id":"DEL001","line_name":"Yellow Line","message":"Critical crowding at Central Secretariat",
  "status":"open","created_at":"2024-12-29T18:02:11Z" } ],
  "meta": { "page":1,"page_size":25,"total":3 } }
```

**POST `/api/v1/alerts/{id}/ack`** → `200 { "data": { "id":"...","status":"acknowledged","acknowledged_by":"<uuid>","acknowledged_at":"..." } }`

**GET `/api/v1/analytics/summary`**
```json
{ "data": { "network_load_pct": 63.4, "active_alerts": 7, "on_time_pct": 88.0,
            "footfall_today": 4210233, "trend": { "footfall_pct": 4.2, "load_pct": -1.1 } } }
```

Full Pydantic schemas live in the backend `schemas/` package (Doc 09); this doc + the OpenAPI spec are the contract.

## 4. WebSocket Events — `/ws/live`

Auth via `?token=<jwt>` on connect; server subscribes the socket to the caller's `assigned_network` room (admins: all). Bridged from Redis pub/sub + Supabase Realtime.

| Event | Direction | Payload |
|---|---|---|
| `connection.ack` | S→C | `{ server_time, replay: {running, speed, clock} }` |
| `replay.tick` | S→C | `{ clock: "2024-12-29T18:00:00Z" }` |
| `crowd.update` | S→C | `{ station_id, crowd_level, occupancy, total_passengers, ts }` |
| `occupancy.update` | S→C | `{ train_id, station_id, occupancy_percentage, crowd_level, ts }` |
| `alert.new` | S→C | full alert object |
| `alert.ack` | S→C | `{ id, status, acknowledged_by, ts }` |
| `schedule.recommendation` | S→C | recommendation object |
| `subscribe` | C→S | `{ scope: "line", value: "Blue Line" }` (optional narrowing) |
| `ping`/`pong` | both | heartbeat |

> PRD lists Socket.IO; if used, these become Socket.IO event names on namespace `/live`. Supabase Realtime is the fallback/parallel channel for DB-change events (alerts, recommendations).

## 5. Error Codes

| HTTP | `code` | When |
|---|---|---|
| 400 | `VALIDATION_ERROR` | bad/missing params (Pydantic) |
| 401 | `UNAUTHENTICATED` | missing/invalid JWT |
| 403 | `FORBIDDEN` | role/RLS denies (e.g. operator apply) |
| 404 | `NOT_FOUND` | unknown station/alert/id |
| 409 | `CONFLICT` | already acknowledged/applied |
| 422 | `UNPROCESSABLE` | semantically invalid (e.g. future_hour in past) |
| 429 | `RATE_LIMITED` | throttled (Redis) |
| 500 | `INTERNAL` | unexpected |
| 503 | `MODEL_UNAVAILABLE` | no active model for task |

## 6. Cross-cutting
- **Rate limiting:** Redis token-bucket per user/IP (limits in Doc 20).
- **Caching:** analytics & heatmap responses cached in Redis with short TTL; `Cache-Control` + ETag.
- **Versioning:** URL-versioned (`/api/v1`); breaking changes → `/api/v2`.
- **CORS:** allow the Next.js origin(s) only.
- **Audit:** all 🔴/mutating calls append `audit_log`.
